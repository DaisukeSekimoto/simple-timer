# Simple Timerの構成とプログラムの役割

## 全体像

画面は引き続き静的なWebアプリです。JavaScriptは`assets/`内のES Modulesをブラウザが直接読み込み、CSSは機能別ファイルで管理します。`npm run build`ではCSSを`assets/styles.css`へまとめ、Service Workerのキャッシュ一覧と更新番号を生成します。実行時のパッケージ依存・APIサーバー・外部CDNはありません。

JavaScriptと分割CSSは`assets/`内を直接編集します。`assets/styles.css`とルートの`service-worker.js`は生成物であり、手で直すと次のビルドで上書きされます。

```text
simple-timer/
├── index.html                  # 画面のHTML、ダイアログ、CSP
├── assets/
│   ├── main.js                 # 起動手順
│   ├── core/                   # 共通定数、計測データ、イベント登録の入口
│   ├── storage/                # ブラウザ保存と既存データの読み込み
│   ├── shared/                 # 日時・時間計算、ファイルダウンロード
│   ├── ui/                     # DOM参照、共通操作、キーボード、通知
│   ├── features/
│   │   ├── timer/              # 計測、ポモドーロ、アプリ内タブ、日付切り替え
│   │   ├── history/            # 履歴の登録・編集・集計・メモ・TXT出力
│   │   ├── todos/              # Todoの登録・期限表示・削除
│   │   ├── tasks/              # 作業名の入力・候補・表記の統一
│   │   ├── settings/           # 設定・テーマ・編集許可
│   │   ├── backup/             # JSON出力、検証、結合・置換
│   │   └── popup/              # 小窓・最小化・Picture-in-Picture
│   ├── styles/                 # 機能別CSS。index.cssが適用順を定義
│   └── styles.css              # ビルドで生成する結合済みCSS
├── service-worker.js           # 内容から更新番号を生成するオフライン用ファイル
├── scripts/                    # ビルドとService Workerの原本
├── tests/
│   ├── unit/                   # 保存・日時・計測の回帰テスト
│   └── browser/                # Chrome/Chromium上の操作テスト
├── docs/architecture.md        # この文書
├── package.json                # 開発コマンドと開発用依存
└── playwright.config.js        # ブラウザテスト設定
```

## 共通部分

| ファイル                            | 役割                                                                                                                           |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `assets/main.js`                       | 保存データを読み込み、入力欄・イベント・描画・オフライン機能を初期化する。別タブからの保存変更を受け取って共有画面を更新する。 |
| `assets/core/constants.js`             | 保存キー、バックアップ形式、計測モード、初期時間、画面サイズの制約。保存キーはここを基準にする。                               |
| `assets/core/state.js`                 | 現在のタイマー、アプリ内タイマータブ、作業履歴、時間表示単位。                                                                 |
| `assets/core/events.js`                | 各機能のイベント登録を一度ずつ呼ぶ。個別のクリック処理は各機能へ置く。                                                         |
| `assets/core/lifecycle.js`             | リサイズとページ終了時の保存・確認。                                                                                           |
| `assets/storage/client.js`             | ブラウザのlocalStorageとsessionStorageを保存アダプターに渡す。各機能には `storage` として公開する。                            |
| `assets/storage/shared-storage.js`     | 項目別の差分保存、削除を示す値、タブ別のタイマー状態。DOMに依存せず単体テストできる。                                          |
| `assets/storage/repository.js`         | タイマー・履歴・日別メモ・勤務時間の読み込み、正規化、保存。旧形式のタイマーもここで引き継ぐ。                                 |
| `assets/shared/time.js`                | 日付キー、時間の表記、入力値の正規化、日をまたぐ時間差。DOMやアプリ状態を参照しない共通計算。                                  |
| `assets/shared/download.js`            | Blobのダウンロードと一時URLの後始末。TXT出力とJSONバックアップで共用。                                                         |
| `assets/ui/elements.js`                | 既存画面のDOM参照を一か所で定義する。Todoも含めて参照を保持し、PiPへのDOM移動後も同じ要素を操作する。                          |
| `assets/ui/activation.js`              | クリックとEnter/Spaceによる同じ操作の登録。                                                                                    |
| `assets/ui/events.js`                  | 共通の閉じるボタン、Undo、キーボードイベントの登録。                                                                           |
| `assets/ui/keyboard.js`                | ショートカットとモーダル表示中の操作優先順位。                                                                                 |
| `assets/ui/toast.js`・`toast-state.js` | 一時通知と取り消し操作、その表示中の状態。                                                                                     |

## 状態と依存関係

`core/state.js` は計測・履歴の共有データを持ち、各機能の `state.js` はその機能の一時的な操作状態を持ちます。保存する内容は `storage/repository.js` または各機能の保存処理が明示的に選びます。確認ダイアログやタイマーのinterval IDを丸ごと永続化することはありません。

処理の基本的な流れは「イベント → 機能の処理 → 状態更新・保存 → 描画」です。関数と状態の参照元はES Modulesのimportに明示され、従来の巨大な関数スコープ内の暗黙参照をなくしています。

既存の画面更新・タイマー操作・保存には相互呼び出しがあるため、機能間には循環importが一部残っています。今回、既存の操作仕様を保つためにこれらをイベントバスへ全面変更することはしていません。機能間の呼び出しは初期化後の関数内で行い、モジュールの読み込み時に他機能の処理を実行しないでください。DOMに依存しない処理は `shared/` または計算専用モジュールへ置きます。

ブラウザ標準のlocalStorageとアプリ用アダプターを混同しないよう、各機能では `storage` という名前でアダプターを利用します。別機能から直接 `window.localStorage` に書くと差分保存を迂回するため、通常は `storage/client.js` 経由にしてください。

## 保存形式と互換性

保存キーとJSONバックアップの形式バージョンは変更していません。既存の履歴・Todo・メモ・タイマーをそのまま読み込みます。

- 履歴とTodoはID単位、日別メモと勤務時間は日付単位で保存します。
- 項目ごとのキーは `保存キー:item:識別子` です。削除は `null` を保存し、別タブの古い一覧による復活を防ぎます。
- 保存前後の差分を使うため、別タブが追加した未読の項目を全件上書きで消しません。同じ項目の競合は最後の変更が優先されます。
- タイマー状態はsessionStorageを優先して復元します。新規ブラウザタブの初期値にはlocalStorage側の最後の保存を使います。
- 「ブラウザのタブ」と、画面内の複数の「タイマータブ」は別の単位です。前者の状態は独立し、後者はそのブラウザタブ内で管理されます。

## CSSの構成

`assets/styles/index.css` が適用順の一覧です。既存の表示を維持するため、分割前のカスケード順を保っています。

| ファイル                                                    | 主な対象                                         |
| ----------------------------------------------------------- | ------------------------------------------------ |
| `base.css`                                                  | 色・テーマ・基本要素・ヘッダー・通知             |
| `timer.css`・`timer-status.css`                             | 計測画面・入力・超過や完了の表示                 |
| `dialogs.css`・`confirmation.css`                           | モーダル、共通入力、確認画面                     |
| `settings.css`・`tasks.css`                                 | 設定表、作業名候補                               |
| `history/list.css`・`rows.css`                              | 履歴の絞り込みと一覧行                           |
| `history/summary.css`・`work-summary.css`・`task-memos.css` | 集計・勤務時間・作業別メモ                       |
| `history/editor.css`・`resumed.css`                         | 履歴編集、日別メモ、計測再開中の表示             |
| `buttons.css`                                               | 主要ボタン・削除ボタン                           |
| `popup.css`                                                 | 小窓と最小化                                     |
| `motion.css`・`responsive.css`                              | アニメーション、動きを減らす設定、狭い画面の調整 |

機能別ファイル中にも、その機能だけに必要なメディアクエリがあります。すべてを最後のresponsive.cssへ移すと適用順が変わるため、そのまま機能側に置いています。

## 整理した重複

- JSONバックアップとTXT出力のBlob URL作成・ダウンロード・解放を `shared/download.js` に統一。
- 追加・編集・カウントダウンの時分秒入力欄への設定を共通化。
- 時刻表示切り替えのクリック・Enter・Space処理を `ui/activation.js` に統一。
- 役割が同じ経過時間取得のラッパーを削除して `getElapsedMs` に統一。
- 使用されていなかった文字幅計算と桁合わせ関数を削除。
- 保存アダプターのキー定義を `core/constants.js` から参照。
- 大きなイベント登録関数を機能別に分割。
- Service Workerの手動バージョン番号更新をビルド時の内容ハッシュに置換。

開始・終了時刻と勤務時間の計算、通常の終了と休憩の早期終了など、似ていても扱う条件が異なる処理は安易に一つにしていません。

## 開発と検証

Node.js 22.13以降とnpmを使用します。ブラウザ操作テストの簡易サーバーにはPython 3を使用します。

```bash
npm ci
npm run build
npm run check
npm test
npx playwright install chromium
npm run test:browser
```

- `npm run build`：配信用JS/CSSとService Workerを生成。
- `npm run check`：未定義参照・未使用変数を検査し、配信用ファイルが現在のソースと一致するか確認。
- `npm test`：複数タブ保存、削除、日時、ポモドーロの休憩除外などを検証。
- `npm run test:browser`：画面操作、Todo、独立したタブ状態、履歴編集、バックアップ、CSP、オフライン再読み込みを検証。
- `npm run format`：編集用ソースとドキュメントの書式を統一。実行後にビルドし直す。
- `npm run build:site`：公開に必要なファイルだけを `dist/` に生成。

既存のChromeを使う場合は `TIMER_CHROME_PATH` に実行ファイルのパスを指定できます。外部で起動済みの検証用サーバーを使う場合は `TIMER_TEST_URL` を指定します。テストは専用の一時ブラウザプロファイルで動き、普段使っているブラウザの履歴を操作しません。

ローカル表示は `python3 -m http.server 8765 --bind 127.0.0.1` を起動して `http://127.0.0.1:8765` を開きます。ビルドしたJSは従来と同じ通常のscriptとして読み込むため、ブラウザ実行時にES Modules用の追加配信設定は不要です。

## 配信とオフライン更新

GitLab Pagesは `dist/` を公開します。開発用の依存・テスト・ソースを公開物へ混ぜません。ビルド済みの `assets/` と `service-worker.js` はリポジトリにも含めるため、ビルド環境のない静的ホストでも必要な公開ファイルを配置できます。

`service-worker.js` のバージョンはHTML・JS・CSS・アイコン・manifest・Service Worker原本の内容から決まります。変更時に自動でキャッシュ名が変わるため、機能追加のたびに手動で番号を上げる必要がありません。更新後は既存タブを再読み込みしてください。

CSPは引き続き `index.html` にあります。ビルド処理はブラウザ実行時の通信を追加しません。通信制限の範囲と限界は [READMEの通信制限](../README.md#ブラウザ側の通信制限) を参照してください。
